## 🌊 Audit Wave Plan (4 Wave Sequential)

### Wave 1 — Skill Manifest Scan (~25 dk)

**Goal:** Her SKILL.md'nin frontmatter'ı, dependency declaration'ı, exec edilebilirlik göstergesi.

**Tasks:**
1. Tüm 43 SKILL.md tam okunur (Lesson 38 v2 — partial inspect YASAK)
2. Her skill için extract:
   - `name`, `description`, `category`, `version`, `status`
   - `mcp_required` (description'dan parse: hangi MCP server'ı çağırıyor)
   - `scripts_called` (inline Python'dan import + subprocess listele)
   - `sub_skills_called` (description veya body'de başka skill referansı)
   - `frontmatter_valid` (YAML parse + required fields check)
   - `body_python_valid` (inline Python block AST parse)
   - `last_modified` (git log -1 SHA + date)

**Output:** `outputs/audits/v1.1-integration-audit/01-skill-manifest-matrix.csv`
- 43 satır × ~10 sütun
- Filter: `mcp_required = true && body_python_valid = false` → blocker
- Filter: `sub_skills_called > 0` → cross-reference kanıt

**Methodology:**
- For each SKILL.md, full body read (Lesson 38 v2 enforce)
- Python AST parse via `ast.parse()` for inline blocks
- grep patterns: `mcp__|claude_code:|skills/|scripts/`

### Wave 2 — MCP Coverage Matrix (~20 dk)

**Goal:** Her skill hangi MCP tool'larını çağırıyor, MCP server connectivity matrix.

**Tasks:**
1. Wave 1 manifest matrix'inden `mcp_required = true` skill'leri filtrele
2. Her skill için MCP function call extraction:
   - Pattern: `mcp__<server>__<tool>(...)` (or similar dispatcher pattern)
   - Subprocess + stdin: `claude_code: mcp <server> call <tool>` (eski pattern)
3. 4 MCP server × 43 skill matrix:
   - gsc → hangi skills (gsc-pull, verify-indexing, monitoring-weekly, vs.)
   - dataforseo → hangi skills (dfs-pull, cluster-map, opportunity, vs.)
   - ScraplingServer → hangi skills (scrapling-ops, competitive-analysis, vs.)
   - Higgsfield → generate-images (yalnız 1)
4. **MCP Server status check** (live):
   - `claude mcp list` çıktısı (connected/offline)
   - Eğer offline ise → blocker (skill çalışamaz)
5. **Tool catalog cross-check:**
   - Each MCP server'ın expose ettiği tool'lar (manifest)
   - Skill'in çağırdığı tool var mı schemas/dataforseo-endpoint-mapping.json + gsc-tool-mapping.json'da?

**Output:** `outputs/audits/v1.1-integration-audit/02-mcp-coverage-matrix.md`
- 4 MCP server × 43 skill grid (X/✓ markers)
- Tool catalog × skill usage table
- Connectivity report (live MCP status)
- Mismatch findings (skill calls non-existent tool, vs.)

**Methodology:**
- Read SKILL.md inline Python tam body
- grep MCP function calls (regex patterns: `mcp_[a-z]+_*\.|mcp__[a-z]+__|claude_code: mcp`)
- ToolSearch lookup MCP server tool definitions

### Wave 3 — Cross-Reference Graph (~25 dk)

**Goal:** Skill-skill, skill-script, script-script reference graph + dead code detection.

**Tasks:**
1. **Skill → Skill references:**
   - SKILL.md description: "use after X skill", "input from Y skill"
   - SKILL.md body: explicit skill name mention
   - rules/events-writer.md branch matrix (skill-event mapping)
2. **Skill → Script references:**
   - inline Python: `from scripts.X import Y` or `subprocess(['python3', 'scripts/X.py'])`
   - SKILL.md "Step N" body: script path mentions
3. **Script → Script references:**
   - Python imports: `from scripts.X import Y`
   - Subprocess: `python3 scripts/X.py`
4. **Skill → Schema references:**
   - JSON schema validation calls
   - schemas/X.json mention
5. **Skill → Rule references:**
   - rules/X.md mention (R-XX cite)
6. **Dead code detection:**
   - Scripts referenced 0 times → unused candidate
   - Skills referenced 0 times by other skills/commands → standalone
   - Schemas referenced 0 times → orphan
7. **Critical workflow chains identification:**
   - Phase 5 (Critical Path): init-project → brand-onboarding → schema-validate
   - Phase 6 (Ingestion): gsc-pull → dfs-pull → scrapling-ops → sf-import
   - Phase 7 (Discovery): tech-audit → on-page-audit → schema-audit → cannibalization → content-decay → content-gaps → competitive-analysis → geo-analysis → quick-wins → aio-competitor-map
   - Phase 8 (Planning): cluster-map → topical-map → new-content-plan → internal-links → master-task-sync
   - Phase 9 (Production): new-blog → revise-content → content-remediation → faq-optimization → generate-images
   - Phase 10 (Publishing): indexing-ping → verify-indexing
   - Phase 11 (Reporting): monitoring-weekly → monthly-report → portfolio-* (7 reporting skills)
   - Phase 12 (Governance): drift-check → schema-validate → glossary-audit → load-context
   - Phase 13 (Meta): brand-onboarding → init-project → mark-done → whats-next

**Output:** `outputs/audits/v1.1-integration-audit/03-cross-reference-graph.md`
- Mermaid diagram (skill chain visualization)
- Adjacency list (skill → skill connections)
- Dead code report (unreferenced files)
- Critical workflow paths (Phase 5-13 traceability)

**Methodology:**
- grep-based reference detection (file path mentions, import statements)
- Build directed graph (NetworkX-style adjacency)
- Detect cycles (should be 0 — DAG expected)
- Phase-based subgraph extraction

### Wave 4 — Workflow Chain Validation + Executability (~30 dk)

**Goal:** Otonom workflow chain'leri doğrula + her skill için minimum executability test.

**Tasks:**
1. **Critical workflow chain dry-run** (no actual MCP calls):
   - Each Phase 5-13 chain step:
     * Input availability check (master.xlsx sheet exists, env vars set, etc.)
     * Output schema match next step's input expectation
     * Event emission point (rules/events-writer.md branch matrix compliance)
2. **Executability test per skill:**
   - SKILL.md inline Python block extracted via `extract_python_blocks` (run_skill_python.py logic)
   - AST parse → syntax valid?
   - Imports resolvable?
   - Required env vars documented in SKILL.md frontmatter?
3. **Mock orchestration:**
   - 1 critical chain end-to-end (örn: Phase 6 ingestion: gsc-pull → dfs-pull)
   - Mock MCP calls (no live API hits)
   - Verify event chain emitted (events.jsonl pattern)
   - Verify state mutation pattern (transaction.update boundary)
4. **Drift detection:**
   - Skills calling deprecated rules (R-XX archived but still cited?)
   - Skills calling deprecated scripts (script renamed but reference stale?)
   - Schema version mismatches (skill expects 1.2 but workspace 1.3?)

**Output:** 
- `outputs/audits/v1.1-integration-audit/04-workflow-chains.md` — chain validation results
- `outputs/audits/v1.1-integration-audit/05-executability-report.md` — per-skill executability scorecard

**Methodology:**
- Use `scripts/ci/run_skill_python.py` extract logic for Python block
- AST parse for syntax validation
- Mock subprocess (no actual exec)
- Phase-by-phase chain trace
